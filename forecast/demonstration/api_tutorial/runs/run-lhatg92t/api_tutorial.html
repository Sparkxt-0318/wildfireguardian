WildfireGuardian API tutorial¶

This notebook demonstrates the saved-model wildfire API and the heat-flux API with the included FishCreek data. Run the cells from top to bottom using Python 3.12. The saved outputs show an executed example; rerunning creates a fresh output directory.

Both prediction APIs return (prediction_matrix, coordinate_matrix). Every coordinate pair is the geographic cell center, ordered (latitude, longitude), in WGS84 degrees (EPSG:4326). Coordinates are static across time.

Input organization Wildfire prediction Coordinates
Raw spatial snapshot (1, H, W) (H, W, 2)
One-step dataset sequence (1, 1, H, W) (H, W, 2)
One sequence (T, 1, H, W) (H, W, 2)
Collated batch (B, T, 1, H, W) (B, H, W, 2)
One heat snapshot (H, W) (H, W, 2)

B is batch size, T is the number of time steps, H is the number of rows, and W is the number of columns. Wildfire predictions remain on the model device; their coordinates are CPU torch.float64 tensors. Heat matrices and coordinates are NumPy arrays.

What the example establishes: how to load data and model parameters, call each interface, inspect missingness, plot outputs, and verify exports and save/reload. The data are retrospective burned-area reconstructions. This tutorial does not establish operational forecast skill or heat-flux accuracy against measurements. The physical heat parameters below are illustrative assumptions.

Use model.load_data for inference: it fixes the checkpoint's channel order and categorical vocabulary. The context manager closes raster readers while leaving returned tensors usable. sequence_length=1 retains one explicit time step.

4. Predict and read the static Earth coordinates¶

The regular result is a tuple. For a sequence, probability[t, 0, row, column] and coordinates[row, column] refer to the same cell. There is no T dimension or singleton channel dimension in coordinates.

Coordinates come from the affine grid and source CRS, converted to WGS84. They identify representative cell centers, not measured flame positions or a subcell burned perimeter. Unknown predictions retain real coordinates; spatially padded cells have (NaN, NaN) coordinates. Temporal padding does not alter the coordinate matrix.

4.1 Inspect validity and family-specific diagnostics¶

predict_sample_details returns the richer result: probability and valid, plus raw_score for the direct family or rate and rate_valid for the exponential family. The raw direct score can lie outside [0, 1]; use the evaluation probability for probability and heat calculations.

This example has many unavailable predictions because the saved model requires complete local context and burned-neighbor contact. Coverage counts do not measure forecast accuracy. Retain unavailable values as NaN.

4.2 Call the API with your own arrays¶

predict accepts the same current tensors and boolean masks plus affine_transform and the source epsg. The six affine coefficients (a, b, c, d, e, f) describe pixel corners; the API converts cell centers using offsets (column + 0.5, row + 0.5).

predict_details needs no geographic metadata. predict_proba returns only probabilities, without coordinates or diagnostic fields. The assertions below verify that the convenience methods agree with the tuple interface.

patch_size requests rectangular spatial patches without resizing the raster. The affine transform is shifted to the patch origin. In an edge patch, pixel_valid=False marks cells beyond the real grid and those cells receive NaN coordinates. 8. Connect the wildfire snapshot to radiant heat¶

WildfireModel.heat_model(...) reuses the loaded wildfire weights and their saved preprocessing. Its predict_sample(sample) method consumes one spatial snapshot and returns:

heat_matrix, heat_coordinates = heat_model.predict_sample(sample)

Both values are NumPy arrays: heat_matrix has shape (H, W) and contains the mean incident radiant heat flux over the next hour, in W/m²; heat_coordinates has shape (H, W, 2) and contains receiver cell-center (latitude, longitude), in WGS84 degrees. The coordinates have no time dimension. Use one heat call per snapshot when processing a sequence.

New burning during an hour differs from active burning at an instant. The heat bridge adds explicit assumptions: conditional on first new burning in the next hour, its time is uniform within that hour; a cell then emits at a constant conditional rate for the supplied burning duration. For new-burn probability $q_i$, forecast duration $D=3600$ seconds, burning duration $\tau_i>0$, and $r_i=\min(\tau_i/D,1)$, the assumed mean and endpoint active probabilities are

$$ \overline p_i=q_i(r_i-r_i^2/2),\qquad p_i(D)=q_i r_i. $$

The rate and geometry parameters below are illustrative scenario assumptions, not measurements for FishCreek. Fuel loading is dry fuel per entire cell area. The modeled rate density is fuel loading × consumed fraction × effective heat of combustion / burning duration. This example calculates radiation from newly igniting cells only; cumulative already-burned cells do not identify existing active flames.

Interpret missing heat and inspect diagnostics¶

In the saved FishCreek example, some possible emitting sources have unresolved new-burn probabilities. Therefore heat_details.complete is False, and the full expected flux matrix is all NaN. This includes receivers whose own wildfire probability is available: radiation from an unresolved source elsewhere in the supplied domain can reach those receivers.

predict_sample_details(...) returns the richer IntegratedHeatPrediction. The known-source contribution remains finite. With the supplied nonnegative source strengths, it equals the lower bound obtained by assigning unknown new-burn probabilities zero; the upper bound assigns them one. These assignments define uncertainty endpoints, not missing observations filled with measured values.

Diagnostic Definition Unit
known_source_heat_flux_w_m2 Contribution from known modeled sources W/m²
heat_flux_lower_bound_w_m2 Lower bound under the fixed supplied assumptions W/m²
heat_flux_upper_bound_w_m2 Upper bound under the same assumptions W/m²
expected_incident_energy_j_m2 Full interval-mean expected flux × 3600 seconds J/m²
incident_energy_lower_bound_j_m2, incident_energy_upper_bound_j_m2 Corresponding bounds on interval incident energy J/m²

The radiation model uses a finite supplied source domain and upward-facing point receivers at cell centers. These bounds exclude outside-domain fires, convection, uncertainty in the physical parameters, and unmodeled heat mechanisms. Incident radiant flux is distinct from absorbed heat or a cell-area average.

Raw inputs and an already computed probability matrix¶

The heat API also accepts raw burned-area/environment arrays, or a previously computed new-burn probability matrix. The configured grid and projected EPSG supply Earth coordinates. Raw heat processing uses one spatial snapshot; any leading dimensions must be singleton.

The probability bridge must receive evaluation probabilities in [0, 1], their validity mask, and a known already-burned mask. For the signed convolution model used here, do not pass its unbounded raw_score. Known already-burned cells have first-new-burn probability zero even where neighborhood context is unavailable.

Positive present-active probabilities can be supplied separately with initial_active_burning_probability and initial_remaining_burning_duration_s; they must refer to known already-burned cells. An unknown_new_burn_probability supplies a separately justified estimate for unsupported cells and is recorded separately in diagnostics. This demonstration leaves those cells unresolved.

9. Standalone radiation without a wildfire checkpoint¶

ExpectedHeatFluxModel.predict(active_burning_probability) takes a complete, finite (H, W) matrix of probabilities of active burning at the same instant, all in [0, 1]. Its returned heat is instantaneous under those inputs; the composed API above instead returns an interval mean after converting next-hour new-burn probabilities into mean activity.

This independent example specifies a small synthetic grid in Korea's projected metric CRS EPSG:5179, with a 10 m cell size and explicit first-pixel-corner origin (1,000,000 m, 2,000,000 m). Its grid and probabilities are illustrative, not observations. The returned receiver coordinates still use WGS84 (latitude, longitude) in degrees.

11. Export arrays and provenance, then verify the saved files¶

Export both predictions and coordinates together, retaining validity masks and source georeferencing. The source projected coordinates are (x, y) in the event's metric CRS; the returned coordinates are (latitude, longitude) in WGS84 degrees. They are stored under different names.

The heat export includes the complete expectation, known-source contribution, physical bounds, and incident energy. For this example, the complete expectation is unavailable; its NaN values are retained. The manifest records the checkpoint checksum, input schema, timing, source CRS, parameter assumptions, library versions, and checksums of generated artifacts. It does not certify the hashes of every original source raster.

12. Optional: train a new model from an existing prepared cache¶

The main tutorial uses a saved checkpoint. Set RUN_TRAINING=True below only when you want to fit a new model. The default execution does not run training. The three-epoch example demonstrates the call and does not reproduce the saved 30-epoch experiment or establish performance.

The cache supplies metadata.json, train.npz, validation.npz, and test.npz. Metadata fixes input channels, kernel size, and whole-fire partitions. The trainer fits normalization on training rows, selects its checkpoint on validation, and reports test metrics afterward. Preserve those event partitions. output_dir must be new or empty.

Use family="exponential" to train the rate-link family instead. Changing model family, training settings, or data defines a new experiment.

13. API reference and interpretation¶

Estimate next-hour active-flame locations model.predict_active_flames_sample(...)

Do not interpret missing probability or heat values as zero. New cumulative burning, instantaneous activity, interval-mean heat flux (W/m²), and interval incident energy (J/m²) are different quantities. Positions are representative grid centers under the saved geometry and stated physical assumptions.

For alternate checkpoints, events, and full scientific/source discussion, use the root README, data contracts, saved reports, and radiation references.
