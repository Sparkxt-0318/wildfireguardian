`check_forbidden` 이 exit 1 로 시작했습니다. 미표시 언급 3건, **전부
`docs/SESSION18_REPORT.md`** — Session 18 이 "ALL TWELVE GREEN" 이라고 적으며
통과시켰다고 여긴 바로 그 파일입니다.

**원인은 지난 세션에 자진 신고한 것보다 나쁩니다.** `check_forbidden.py` 와
`check_number_collisions.py` 는 파일 목록을 `git ls-files` 로 만드는데, 그것은
**이미 추적 중인 파일만** 나열합니다. Session 18 의 커밋 연쇄는 게이트를 돌린
**뒤에** `git add -A && git commit` 했으므로, **그 커밋이 새로 도입하는 파일은
게이트에 보이지 않았습니다.** 각 세션 보고서 자신이 그랬습니다. 프로브로
확인했습니다 — 금지 토큰을 담은 미추적 파일은 exit 0 입니다.

즉 Session 18 중반에 도입한 `&&` 연쇄는 **틀린 절반을 고쳤습니다.** 빨간
게이트 위 커밋은 막았지만, 게이트 자체가 **가장 틀리기 쉬운 파일에 눈이
멀어** 있었습니다.

**구조적 수정:** 두 게이트 모두 이제
`git ls-files` **∪** `git diff --cached --name-only --diff-filter=d` 를
훑습니다. 스테이징 순서와 무관하게 옳으며, 작성자가 안전한 순서를 기억하는
데 의존하지 않습니다. 양방향 프로브로 확인했습니다.

수정 후: 게이트 12개 exit 0, `verify_numbers` **237/237**, 테스트
**1,116 passed / 3 skipped / 1 xfailed / 0 failed**. 녹색 확인 후 진행.

### 판독기 — 모든 상수가 파일에서 나오고, 두 가지는 실측으로 정했습니다

교정 상수를 기억이나 문헌에서 가져오지 않았습니다. 전부 granule 의 전역
속성입니다. 다만 **두 가지는 읽을 수 없어 실증적으로 확정**했고, 둘 다
**점검이 잡았지 눈으로 찾은 것이 아닙니다**:

1. **복사휘도 단위.** 파장당 W·m⁻²·sr⁻¹·μm⁻¹ 로 읽으면 8.7 μm 장면이
   **311–466 K** — 불가능. 파수당 **mW·m⁻²·sr⁻¹·(cm⁻¹)⁻¹** 로 읽고 Planck
   파수형으로 역산하면 **226 / 279 / 298 K** — 찬 구름 정상, 3월 지표, 따뜻한
   지면. 후자가 단위입니다.
2. **유효 비트 수는 채널마다 다릅니다.** ir087·ir112 는 13비트지만 **sw038 은
   14비트**입니다. 13으로 마스킹하니 전 장면이 **376 K** 였는데, 이 값은
   화소 단위 점검창(150–400 K) **안**이라 통과했습니다. **장면 중앙값
   점검**(180–330 K)을 추가해 잡습니다.

지오로케이션은 파일 자신의 모서리 속성과 **소수 셋째 자리까지 일치**하고,
최근접 화소 오차 0.9–1.4 km 로 2 km 격자에서 부화소입니다.

### ⚠ 배경 오염 — 방법 결함을 찾았고, 두 추정량을 모두 남겼습니다

**영덕과 의성은 같은 날 66 km 떨어져 발화** — 서로의 30–80 km 배경 고리
안입니다. 의성이 ΔT ≈ 67 K 로 타면서 영덕 고리의 표준편차를 ≈ 4 K 로 올렸고
4σ 문턱이 **20 K 를 넘었습니다.** 깨끗한 야간 장면은 산포 0.49 K 입니다.

로버스트(중앙값 + 1.4826·MAD)를 주로 읽되 **선언된 평균/표준편차도 모든
스텝 레코드에 남겼습니다** — 바꿔치기가 아니라 변경으로 보이도록. **K 는
양쪽 4 로 동일**하고, 어느 쪽도 탐지를 본 뒤에 고르지 않았습니다.

### ⚠ 영덕 — 제 초고가 틀렸고, 근거 숫자는 저장소에 없었습니다

초고는 "**문턱 탓이 아니다**"라고 적으며 표적 구역 통계
**5.09 / 0.89 / 8.65 / 7.34 K** 를 들었습니다. **그 네 숫자는 어떤 커밋된
산출물에도 존재하지 않습니다** — 스텝 레코드에는 `target_delta_max_k` 만
있고 표적 구역의 중앙값·MAD 필드 자체가 없습니다. 재유도할 수 없는 수치는
이 저장소의 출처 규칙상 설 수 없으므로 **철회합니다.**

커밋된 레코드만으로 다시 유도하니 **결론이 뒤집혔습니다**
(`scripts/gk2a_yeongdeok_diagnostic.py`,
`data/processed/detection/yeongdeok_background_contamination.json`):

| | 실측 |
|---|---:|
| 표적 구역 최강 이상 | **11.611 K** @ 03:42 UTC = **신고 +28분** |
| 그 스텝의 문턱 | **21.964 K** |
| 그 스텝의 **배경 고리** 중앙값 | **8.328 K** (깨끗한 야간 장면 **1.13 K**의 **7.4배**) |
| 깨끗한 배경이었다면 문턱 | **3.09 K** → 11.611 K 가 **8.5 K 차이로 통과** |

**즉 영덕의 「미탐지」는 화재도 GK2A 감도도 아니라 배경 고리를 잰
것입니다.** 원인은 §Phase 1 에 이미 적힌 그것 — **의성이 66 km 떨어져
영덕의 배경 고리 안에서 ΔT ≈ 67 K 로 타고 있었습니다.**

⚠ **그렇다고 탐지로 바뀌지 않으며, 그렇게 세지 않았습니다.** 깨끗한 문턱
3.09 K 기준으로는 **283스텝 중 217스텝**이 통과하는데 **신고 몇 시간 전
스텝까지 포함**됩니다. 주간 배경 대비가 태양 반사만으로 +6…+8 K 이므로
3.09 K 는 주간에 지나치게 헐겁고, **통과가 곧 불의 증거가 아닙니다.**
11.611 K 이상을 **불이라고 동정하지 않습니다.**

> **바뀐 것:** 영덕은 **null 이 아니라 교란 사례**이며 증거 기반에서
> **제외**됩니다. 탐지로도, 위성이 못 본 사례로도 세지 않습니다.
> **바뀌지 않은 것:** 평결. 표본이 4→3 으로 줄 뿐이고, 영덕의 이상을
> 화재로 읽더라도 **+28분**이라 여전히 신고보다 뒤입니다.

## Phase 2 — 바닥의 성격

**오경보: 709 대조 스텝 중 0건.** 같은 지점·같은 시각대·14일 전(계절·태양
고도·지형·해안선 고정, 불만 제거). ⚠ **"오경보 없음"이 아니라 상한입니다** —
709회 0건의 95 % 상한은 스텝당 약 0.4 %, 2분 주기로 **하루 3건 수준**일 수
있습니다.

**크기 바닥: 대략 0.1–1 ha.** 가장 약한 탐지(의성, ΔT 22.9 K)에서 Dozier
2성분 분해: 화염 온도 600/750/900 K 가정에 대해 **0.69 / 0.19 / 0.08 ha**.
⚠ **화염 온도는 가정이며 그것만으로 값이 8배 이상 움직입니다.** 소수점을
읽지 마십시오.

**구름·야간.** 강릉은 탐지 시점 표적의 **40 %가 273 K 미만**(부분 운량)이고
문턱도 62.1 K 로 유독 높았습니다 — 맑았다면 더 일렀을 수 있으나 **재지
못했습니다**. **탐지 3건 모두 주간**(08:56/11:46/12:04 KST)이라 **야간
성능은 이 표본에서 측정되지 않았습니다.** 가시 4채널은 밤에 무용하며 이
측정에 쓰지 않았습니다(적외 2채널만).

**GK2A 대 FIRMS.** 3건 중 **2건에서 GK2A 가 95분·117분 빨랐고**, 홍성에서는
**FIRMS 가 47분 빨랐습니다**(VIIRS 통과가 마침 그때). 맞바꿈은 평균적으로
GK2A 유리, 개별 사건은 통과 시각 운. **n = 3 입니다.**

## 주장하고 싶었으나 검증하지 못한 것 *(필수 항목)*

1. **발화 대비 지연을 재지 못했습니다.** 기준이 신고 시각이라는 것이 이
   측정의 **가장 큰 한계**이고, 실제 발화 시각을 담은 자료는 이 저장소에
   없습니다(Session 17·18 의 산불통계데이터 장벽과 같은 자료가 필요합니다).
2. **영덕의 나머지 원인을 분리하지 못했습니다.** 배경 교란은 이제 **측정된
   요인으로 확정**되었지만, 좌표가 틀렸는지·시각이 틀렸는지·불이 늦게 그
   좌표에 도달했는지는 여전히 **분리하지 못했습니다.** 그리고 11.611 K
   이상이 화재인지 주간 태양 오염인지도 **가르지 못했습니다** — 가르려면
   깨끗한 배경 고리를 다시 잡아 재실행해야 하고, 그것은 하지 않았습니다.
2b. ⚠ **자진 신고: 이 보고서 초고의 영덕 근거 숫자 네 개는 저장소에 없는
   값이었습니다.** 게이트가 잡지 못했습니다 — `verify_numbers` 는 **등록된**
   항목만 재유도하고, 산문 속 미등록 숫자는 검사 대상이 아니기 때문입니다.
   Session 18 의 충돌 스윕도 **등록된 양**에 앵커링되어 있어 같은 이유로
   보지 못했습니다. **산문 속 미등록 수치를 산출물에 대조하는 게이트는 아직
   없으며, 이번에도 만들지 않았습니다.**
3. **강릉의 구름 효과를 정량화하지 못했습니다.** 40 % 운량과 62.1 K 문턱을
   보고했지만, 맑았다면 몇 분 빨랐을지는 **재지 않았습니다.**
4. **야간 성능은 측정되지 않았습니다.** 탐지 3건 모두 주간입니다. 야간이
   더 쉬울 것이라는 서술은 **추론이며 이 표본의 측정이 아닙니다.**
5. **오경보율은 4지점·1계절입니다.** 전국·연중이 아니고, 대조 기간에
   실제로 불이 없었다는 것도 **FIRMS 로 교차 확인하지 않았습니다.**
6. **크기 바닥의 화염 온도는 가정입니다.** 그리고 표본이 **탐지 3건**입니다.
7. **배경 고리의 육/해 혼합을 분리하지 못했습니다.** 영덕 고리의 40 %가
   바다이고, 그것이 MAD 를 정당하게 키웁니다. 의성 오염과 이 요인의 기여를
   **나누지 못했습니다.**
8. **탐지기를 FIRMS·KMA 산출물과 화소 단위로 대조하지 않았습니다.** 비교는
   **첫 탐지 시각**끼리이며, 같은 사건에 대한 화소 일치도는 재지 않았습니다.
9. ⚠ **Session 18 의 "ALL TWELVE GREEN" 은 그 커밋들이 새로 만든 파일에
   대해서는 공허했습니다.** 위 Phase 0 에 원인과 구조적 수정을 적었습니다.
