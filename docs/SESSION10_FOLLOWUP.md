## 과제 1 — 숨기지 않고 스위트를 초록으로

**결과: 완료. 1건의 `xfail`, 범위는 RandomForest 단 하나.**

지시대로 기존 테스트에 통짜 `xfail` 을 씌우지 않았습니다. 그렇게 하면
`hist_gbm` 이 나중에 드리프트해도 `xfail` 로 보고되어, **이 테스트가 존재하는

테스트 1개를 5개로 분할했습니다. 비싼 부분(151,904행 데이터셋 재구축 + 2회
compute)은 **module-scoped fixture** 로 한 번만 돌므로 **런타임은 그대로**
입니다 (128초 → 125초).

| 테스트 | 성격 | 결과 |
|---|---|---|
| `test_compute_payload_is_deterministic_under_the_fixed_seed` | 엄격 | PASS |
| `test_the_dataset_shape_regenerates_exactly` | 엄격 | PASS |
| `test_hist_gbm_calibration_regenerates_exactly` | **엄격 — 보고되는 모델** | PASS |
| `test_logistic_calibration_regenerates_exactly` | 엄격 | PASS |

`xfail` 사유 문자열은 원인(스레드별 부동소수점 누적 순서, BLAS 빌드)과

`strict=False` 이므로 **참조 환경에서는 재현되어 `xpass`** 합니다.

**삭제한 단언 없음. 완화한 허용오차 없음. 플랫폼 조건부 없음.**

## 과제 2 — 게이트 러너 종료 코드 버그

**결과: 완료. 두 겹 방어 + 재현 검증.**

원인: POSIX 셸에서 파이프라인의 종료 코드는 **마지막 명령의 것**입니다.
`게이트 | tail` 은 게이트가 실패해도 `tail` 의 0 을 돌려주고 `&&` 연쇄가
진행됩니다. 게이트는 옳았고, 호출 방식이 그 종료 코드를 버렸습니다.

**(1) `Makefile`** 이 이제 `SHELL := /bin/bash`,
`.SHELLFLAGS := -o pipefail -e -c` 로 실행됩니다. `-u` 는 의도적으로 넣지
않았습니다 (비어 있을 수 있는 변수를 참조하는 레시피가 있습니다).

재현 검증 — 같은 레시피, 파이프 안의 명령이 실패:

| | 결과 | `make` 종료 코드 |
|---|---|---|
| 기존 `/bin/sh` | `REACHED COMMIT (bad)` 출력 | **0** ← 버그 |
| 새 `SHELLFLAGS` | `make: *** Error 1` | **2** ← 정지 |

**(2) `scripts/check_gate_invocations.py`** — 추적 대상 셸·Makefile·CI·
문서의 **실행 가능한 코드 블록**에서 pipefail 없이 파이프 뒤에 놓인 게이트
호출을 찾아 실패시킵니다. `make verify` 의 다리로 편입했습니다.

⚠ **이 검사기의 첫 판본은 오탐 3건을 냈습니다.** 마크다운 펜스 상태를
셸 펜스에서만 토글해서, ```` ```python ```` 블록의 닫는 펜스가 여는 펜스로
읽히고 그 뒤의 표 행들이 전부 "셸 블록 안"이 되었습니다. 표의 `|` 는 파이프가
아닙니다. 펜스 열림/닫힘을 블록 종류와 독립적으로 추적하도록 고쳤습니다.
**늑대를 외치는 게이트는 꺼지고, 그 비용이 원래 버그보다 큽니다.**

`README.md` 에 올바른 실행법과 이 사고 기록을 넣었습니다.

## 과제 5 — 라벨 기하: 방향은 애초에 복원 가능한가

**결과: 완료. 가설은 지지되지 않았고, 더 유용한 것이 나왔습니다.**
전문·그림 6장: `docs/label_geometry_analysis.md`.

### 측정

화재별·라벨 스텝별로 새로 연소된 셀의 방위 분포를 두 기준계(직전 발자국
중심 / 최근접 직전 활성 셀 = `wind_alignment` 의 기준계)에서 계산하고,
집중도 `R = |단위벡터 평균|`(1=단일 방향, 0=등방), 전진비, ERA5 바람
방위와의 각도차를 구했습니다. 새 셀 5개 미만인 스텝은 `usable=false` 로
표시했습니다 (58개 중 36개 사용 가능).

### 결과

| 항목 | 값 | 읽는 법 |
|---|---:|---|
| `R` (통합) | **0.601 ± 0.294** | **등방과 거리가 멉니다** |
| `R` vs 스텝 길이 상관 | **+0.170** | 가설은 **음**을 예측 — 부호가 반대 |
| 관측 방위 vs ERA5 바람, 원형상관 | **−0.053** | 관계 없음 |
| 관측 방위 vs ERA5 바람, 평균 각도차 | **75.45°** ⚠ S11 에서 **83.5°** 로 갱신 | 무관계면 90° |
| 폴드별 바람 원형상관 | −0.260 ± 0.200 (4개 폴드) | 전부 음수 — 부호는 미해석 |
| 방위 지속성 (k → k+1), 통합 | **−0.195** (연속 쌍 21개) | 이 주기에서 관측 불가 |
| 연속 스텝 간 평균 방위 변화 | **43.26°** | 매 관측마다 재정렬되어 보임 |

### 평결

**가설은 지지되지 않습니다.** 방향 신호는 라벨에 **존재하며**(통합
`R = 0.601`, `uljin_samcheok_2022` 은 0.809), 스텝이 길어져도 씻겨나가지
않습니다(상관 +0.170, 예측과 반대 부호). **적분되어 사라지는 기전은
시연되지 않았습니다.** 따라서 두 null 은 "타깃이 등방적이어서"가 아닙니다.

**그러나 존재하는 그 방향은 두 전제 어느 쪽과도 맞지 않습니다.**

- `wind_alignment` 는 *라벨의 방향이 ERA5 바람을 따른다*를 전제합니다 →
  원형상관 −0.053, 각도차 75.45° (Session 11 에서 구간 벡터평균 기준
  **83.5°** 로 갱신 — 전제는 더 강하게 기각됩니다).
- `obs_alignment` 는 *직전 스텝의 방향이 이어진다*를 전제합니다 →
  스텝 간 평균 43.26° 재정렬되어 보이고 통합 상관 −0.195 — 이 주기에서
  관측할 수 없다는 뜻이며, 지속성이 없다는 뜻은 아닙니다.

**이것이 두 null 을 특징 품질을 탓하지 않고 설명합니다.**

⚠ **Arm D 를 사후적으로 구제하는 데 쓰지 않았습니다.** Arm D 는 여전히
pooled·far-band·cold-start 어디서도 이득이 없습니다. 달라진 것은 *설명*이지
*결과*가 아닙니다.

**Arm C 는 동기를 회복합니다.** 지시서의 조건문 그대로입니다 — 방향이
존재하므로 null 은 진짜로 특징에 관한 것입니다. 라벨에 방향이 있고 ERA5 가
그것을 가리키지 않는다는 간극은 이제 **추정이 아니라 측정값**입니다.
⚠ **WindNinja 가 그 간극을 메운다는 뜻은 아닙니다** — 측정되지 않았습니다.
