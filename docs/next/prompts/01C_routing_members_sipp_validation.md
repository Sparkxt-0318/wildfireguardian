## Why this track exists

Three facts from the code and evidence:

1. Scenario members are built by independent per-cell Bernoulli draws from marginal probabilities with uniform ignition timing (`bridge.draw_ignitions`). The docstring itself calls this "a declared research assumption, not a calibrated joint forecast". Independent draws produce scattered burn maps rather than a coherent fire, so "safe in all 4 members" is neither a conservative nor a calibrated statement about a road being cut.
2. The search is a 1 second time-expanded sweep over (edge, second, admission). It is exact for the relaxation but its cost scales with the horizon in seconds times the edge count; the Caldor panel is the first case where the baseline hit the 30 s deadline on every attempt, and the October 29 repair had to bind radiation work to the request window to recover. A search whose states are safe intervals rather than seconds removes that scaling.
3. There is no observed vehicle-evacuation data to validate against, and there will not be for a long time. The honest substitute, standard in weather science, is an observing system simulation experiment: hide a "truth" fire from the router, give it only the forecast, execute its decision against the truth, and measure what happens. That is also the only way to answer the project's own question, how good a forecast must be before it should change a protective decision.

## Deliverable 2: Safe Interval Path Planning (`experimental/sipp-routing/`)

Implement SIPP (Phillips and Likhachev 2011, IEEE ICRA, pp. 5628-5635) for the contact-only relaxation Z and prove it reproduces the existing sweep. Read the paper first: a safe interval is a maximal contiguous collision-free period for a configuration; the state is (configuration, safe interval) with the earliest arrival time stored as a label rather than as part of the state identity; successors are generated per reachable safe interval of the neighbour with "wait then move" to the earliest feasible arrival; keeping only the earliest label per state loses nothing because an earlier arrival within an interval can wait and reach every successor a later arrival can (their Theorem 1), and the first goal expansion is time-optimal (Theorem 2). This holds only when cost equals time, waiting is allowed in the configuration, and the heuristic is consistent; if you ever minimize anything other than arrival time (exposure, waiting penalties), you need the generalized dominance of Gonzalez, Dornbush and Likhachev (ICRA 2012) or you silently lose optimality. The closest prior road-network applications are Wang and Zlatanova (2020, IEEE Transactions on Intelligent Transportation Systems 21(3):1044-1053, safe routes for first responders with moving obstacles) and Shahabi and Wilson (2017, Computers, Environment and Urban Systems 67:29-40); no published paper applies safe intervals explicitly to wildfire or flood evacuation, which you may state as a gap if you cite the temporal-graph and time-dependent shortest-path work (Orda and Rom 1990; Dean 2004) as the operations-research precedent.

1. Safe intervals: for each directed edge and each waitable node, compute the maximal time intervals during which traversal (respectively waiting) has no flame contact in any member (union of member activity intervals, using exactly the sweep's occupancy semantics from `core.edge_occupancies`: sub-segments between grid cuts with midpoint cells and cut points with floor cells, closed cell footprints, half-open activity intervals). Edge traversal takes `travel_ticks * dt` seconds; an edge is usable during a safe interval only if the whole occupancy of every sub-segment is contained in a safe interval of that sub-segment's cell (compute per sub-segment, then intersect along the edge with the appropriate time shifts).
2. Search state: (directed edge just traversed, safe-interval index of that edge's arrival, admission flag), with the incoming edge retained for turn restrictions exactly as the lattice grammar does. Earliest arrival time within each state is the label. Waiting is allowed only at waitable nodes and only within a node safe interval; the standard SIPP successor generation computes the earliest arrival into each successor safe interval (arrive as early as possible, wait if needed, never wait past the end of the current safe interval). Destination admission uses the same opening-interval and dwell rules as `zsweep.py`.
3. Optimality and completeness: with A* ordering by earliest arrival plus an admissible static lower bound on remaining travel time (reuse the existing backward Dijkstra bound), SIPP returns the earliest arrival of the relaxation; exhausting the open list proves no route exists (a model-scoped refusal). Write `docs/SIPP_EQUIVALENCE.md` explaining why the safe-interval states dominate the 1 second lattice states and listing every assumption (integer seconds, FIFO edges, waiting only at waitable nodes).
4. Differential testing: on all 26 missions, both repetitions, SIPP must return exactly the same arrival second and the same refusal verdicts as `zsweep.contact_sweep` (run the frozen sweep through a copied adapter). On 10,000 random small instances (hypothesis: random graphs with 5 to 30 nodes, random turn restrictions, random member activity intervals, random destination windows), SIPP must match a brute-force time-expanded search. Any mismatch is a bug in SIPP until proven otherwise.
5. Cost: states expanded, wall time and peak RSS per mission versus the sweep, on the Korean panel and on Caldor/Rim, within the same 30 s and 3,072 MiB limits and the same ABBA ordering, two repetitions. Also report the state count as a function of the number of members, since safe intervals fragment as members are added (this is the cost of K = 32).
6. Chance-constrained search variant (optional, after 1 to 5 are done). Two exact options; implement the first, and the second only if time allows. (a) Subset enumeration: enumerate member subsets S whose retained weight is at least 1 - alpha, in decreasing weight order, run plain SIPP on the union of unsafe intervals of S, and stop at the first feasible subset; feasibility is monotone (every superset of an infeasible subset is infeasible), which prunes the lattice; for m = 8 this is at most 256 SIPP runs, far inside 30 s once SIPP itself is fast. (b) Bitset labels: carry the set of violated members in each label with dominance by subset (a label dominates another at the same state if it is no later and its violated set is a subset of the other's); exact, but label counts can grow quickly. The literature precedent for soft constraints inside SIPP is SIPPS (Li et al. 2022, AAAI, MAPF-LNS2), which counts soft collisions as a scalar lower bound and is exact only when a zero-violation path exists; cite it, but do not rely on it for the certificate. Report state growth versus m up to m = 16 and stop if it exceeds the budget; a post-hoc `k_of_m` on the Z candidate remains the fallback.

7. Dose stays outside the intervals. Cumulative exposure is a resource, not an interval constraint, so it cannot be encoded as a safe interval. The pattern is lazy constraint generation: plan with the interval model (flame contact, and peak flux once track 1A's law makes it bind, since both depend only on (edge, time)), verify dose in the checker, and if a certified-contact candidate fails the dose check, add the offending (edge, time window) to the unsafe set and replan, with a documented iteration cap after which the mission is unresolved. The exact alternative is a resource-constrained shortest path, pseudo-polynomial in the dose discretization, which is what the reference implementation already is.

8. Verification culture, cheaply: write the journey-safety predicate as mathematics in `docs/JOURNEY_SAFETY_PREDICATE.md` (a journey is a sequence of (edge, entry time, exit time) with optional node waits; it is safe under member set S iff for every leg and member: the traversal window does not intersect the member's unsafe interval of that edge, flux stays below the peak limit, node waits lie inside node safe intervals, legs are contiguous, times are monotone, turn restrictions hold, the dose sum is within budget, departure is at or after issue, and the destination window and dwell hold), give every clause a requirement identifier, and trace each identifier to the checker function and to at least one test. Add metamorphic tests with Hypothesis: adding unsafe intervals never decreases the optimal arrival time; removing members never makes a certified journey unsafe; a journey certified under the union of members is certified under each member alone; shifting all times by a constant shifts the solution by the same constant; relabelling edges changes nothing. Frame the design as a certifying algorithm (McConnell, Mehlhorn, Naher and Schweitzer 2011): the planner is the unassured complex function, the checker is the assured monitor, and "unresolved" is the recovery output, which is the runtime-assurance pattern of ASTM F3269-21.

Evidence `research/sipp-routing/README.md`: equivalence counts first (26/26 identical, N/10,000 property cases), then the cost table and `fig01_time_vs_sweep_paired`, `fig02_states_vs_members`, `fig03_caldor_breakdown`. If SIPP is not faster on some panel, say so and explain where the time goes.
