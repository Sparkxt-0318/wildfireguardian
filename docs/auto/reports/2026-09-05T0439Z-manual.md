## In plain terms

**What failed.** The gate that stops the paper claiming a satellite saw these fires before a
human called them in went red — not because anything got worse, but because it was counting
sentences, and the paper routine rewrote one of them. It broke on the paper routine's push;
the red only showed up one push later, on a commit that changed no code, because GitHub had
cancelled the run that would have caught it.

**Why only on GitHub.** It wasn't only on GitHub — it failed here too, the same way. The
branch really was broken for about fifty minutes, and it is green again now.

**What changed.** Nothing needed fixing by the time this ran: the 03:33 build lap had already
made the same fix, and made it better. So this lap kept the one thing it found that nobody
had written down — the gate has a hole. It ignores any sentence containing "not", "no",
"never" or "unknown", on the assumption that such a sentence must be *withdrawing* the claim.
It doesn't have to be: "the satellite fired 22 minutes after the human report, **not** the
other way round" states the forbidden claim outright and sails through. Filed as **WFG-099**
for a lap that can do it properly — this is the gate protecting four judge-facing documents,
and narrowing it wrongly would be worse than the hole.

**What you should do.** Nothing urgent. Two things to know: the loop had two routines fix the
same failure twenty minutes apart, because a red run — unlike a backlog row — has no way for
one routine to tell another it is already on it (MEMO entry added, with the cheap fix). And
`auto-gates` cancels a superseded run, so a commit that is overtaken within two minutes is
never checked on a clean machine and the next commit inherits its red — that is what made a
one-line backlog claim look like the cause of this one.
