# Session 14 보고서 — Layer 0: 발화 전 대피 취약도

다른 모든 층은 **화재 위험**을 예보합니다. 이 층은 **불이 나면 누가 갇히는가**를
예보합니다 — 발화 이전에.

실행 기록·인벤토리·사전 설계: [`docs/SESSION14_LOG.md`](SESSION14_LOG.md)
이식성 감사: [`docs/global_portability.md`](global_portability.md)

## 1. 점수 정의와 근거

> **취약도 = 표집 시나리오 중 (a) 생존 가능한 자력 대피 경로가 없거나
> (b) 여유 마진이 10분 미만인 시나리오의 비율.** 두 성분은 항상 분리 보고.

**왜 순수 "경로 없음" 비율이 아닌가.** 영덕에서 그 정의는 **전 가구 정확히
0** 입니다. 마진 문턱을 더하면 점수가 여전히 *실패 횟수*(운영자가 행동하는
단위)이면서 "2분 남기고 탈출"을 실패로 셉니다. 마진 분위수를 쓰지 않은 이유는
경로가 없는 가구에는 평균할 마진이 없기 때문입니다 — "절대 못 나감"과 "간신히
나감"이 뭉개지지 않아야 합니다.

⚠ **영덕에서는 문턱을 더해도 여전히 0입니다** (§2). 정의를 바꿔 흥미로운
숫자를 만들지 않았습니다.

OSM 가옥은 **갇히지 않습니다.** 구속 조건은 화재 거동이 아니라 **피난처
밀도**입니다.

### 발화 표집 스윕 (Phase 1a)

| uniform n=4 / 8 / 16 | 0.000 / 0.000 / 0.000 | 0 / 0 / 0 |

**"가구 순위가 스윕에서 안정적인가"라는 질문은 여기서 공허합니다** — 점수에
분산이 없으므로 **순위 자체가 존재하지 않습니다.** 이는 스윕의 실패가 아니라
스윕이 드러낸 사실이며, 지시서가 요구한 "절대값은 움직이되 순위는 안정"이라는
바람직한 성질이 이 데이터에서는 **검정 불가**임을 뜻합니다.

### 위험원 민감도 (Phase 1c)

플러그형 인터페이스는 구현했고 (`hazard_sources.py`: `EllipticalHazard`,
`TrainedModelHazard`), **두 위험원 사이 순위 변화는 측정하지 못했습니다** —
타원 위험원 쪽 순위가 상수(전부 0)이므로 상관이 정의되지 않습니다. 학습
모델과의 비교는 **미실행**이며, 그렇게 기록합니다.

있다"** 는 구조적 사실입니다. 소방관 인터뷰의 "한 템포 느리다"에 대한 답은
이 구조이지 이 숫자가 아닙니다.

## 3. Phase 2 — 정직한 경계

## 6. 주장 규율 점검 (요구 항목)

이 세션의 산출물 전체를 다시 읽고 확인했습니다.

- ✅ **FWI-Net 보다 정확하다는 문장 없음.** 비교는 `global_portability.md`
  §4 한 곳뿐이며, **규모와 대상**(국가 대 가구, 1° 대 500 m, 스칼라 지수 대
  가구별 대피 판정)에 한정되고, "벤치마크는 존재하지 않고 여기서 수행할 수도
  없다"를 명시했습니다. 그들의 모델을 개선한다는 문장도 없습니다.
- ✅ **학습 확산 모델이 한국 밖으로 이전된다는 함의 없음.** 반대로
  `global_portability.md` §2c, `hazard_sources.py` 모듈 독스트링,
  `vulnerability_portability_run.py` 독스트링, 본 보고서 §4에서 **네 번**
  미국 이전 실험 수치(0.0128–0.0273 대 문턱 0.3)를 들어 이전 불가를
  명시했습니다. Phase 4 는 학습 모델을 **사용하지 않았고**, 산출 JSON 에
  `"trained_model_used": false` 를 기록했습니다.

## 8. 주장하고 싶었으나 검증하지 못한 것 *(필수 항목)*

1. **"영덕 가구는 안전하다."** 주장하지 않습니다. 측정한 것은 *이 가정
   하에서* 취약도가 0이라는 것입니다. 더 강한 화재, 더 긴 지평, 실제로
   사용 가능한 피난처만 센 집합에서는 달라질 수 있고, **어느 것도 시험하지
   않았습니다.**
2. **위험원 민감도 (Phase 1c 의 핵심 요구).** 두 위험원 사이 순위 변화를
   **측정하지 못했습니다.** 타원 쪽이 상수라 상관이 정의되지 않습니다.
   학습 모델 위험원은 실행하지 않았습니다.
3. **타원 위험원의 보정.** `base_ros = 2.0 m/min`, `beta = 0.05`,
   중간불꽃 풍속 계수 **0.4** — 전부 문헌 관행에서 가져온 가정이며 한국
   연료에 대해 **보정된 바 없습니다.** 이 중 어느 것도 스윕하지
   않았습니다. 개발 중 두 개의 실제 버그를 잡았습니다(바람이 타원 모양만
   바꾸고 속도를 못 바꾸던 것, 10 m 풍속을 중간불꽃 풍속으로 잘못 넣던
   것) — 남은 버그가 없다는 보장은 없습니다.
4. **관련성 반경 5 km.** 근거는 적었으나 **값을 스윕하지 않았습니다.**
5. **Paradise 의 53가구가 실제로 위험했는가.** 알 수 없습니다. §5c.
6. **피난처의 실제 사용 가능성.** OSM `amenity=school` 이 화재 시 열려
   있는지, 수용 가능한지 **모릅니다.** 영덕의 0이 이 낙관적 가정의 산물일
   가능성이 큽니다.
7. **Mati·Pedrógão 사이트 사실.** 커버리지만 셌고 **사건 사실을 인용
   가능한 출처로 확인하지 않았습니다** — 그래서 게이트 JSON 에
   `"not verified in this session"` 으로 기록했습니다. Paradise 만
   확인했습니다.
8. **커버리지 게이트의 실패 질의.** Paradise 의 도로·피난처 질의와 영덕의
   피난처 질의가 Overpass 에서 실패했습니다. 재시도하지 않았고, 그 칸은
   비워 두었습니다.
9. **FWI-Net 논문 원문.** Discussion 의 취지는 지시서가 전한 대로 인용
   했으나, **논문 본문을 직접 열어 확인하지 않았습니다.**
