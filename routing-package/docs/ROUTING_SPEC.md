# Routing specification — 4 October 2026

Evidence: runnable engineering on declared thermal fixtures. No forecast accuracy, physical safety, real-fire validation, or novel-algorithm claim follows from this specification.

## Problem and objective
For each declared scenario member m, choose an earliest destination **arrival**, with the destination admissible throughout its required dwell. Directed edges and incoming-edge forbidden turns define legal moves. Every route remains on the mapped straight road chords. Assume declared best-case vehicle/passability. Traffic, debris, pedestrian routes, fleet scheduling and pickup are outside this contract. Cycles are legal. Required dwell must end by the absolute mission horizon and fit a single inclusive destination opening interval.

A state is (node, incoming edge, absolute lattice time, admission event, per-member incurred-plus-route dose). At an interior directed-road position, the first action completes its residual fraction. Mid-edge reversal requires the graph's explicit permission, an explicit mutual reverse edge, allowed reversal turn and an exactly representable mirrored fraction. Historical Nangok forbids mid-edge reversal. Residual duration is the ceiling of exact represented remaining fraction times declared edge ticks, multiplied by dt; this is a conservative discrete travel model. It is not measured vehicle dynamics. Fraction 1 normalizes to the edge head with incoming context retained; fraction 0 requires an explicit node and actual incoming context.

An initial node or edge arrival creates a destination admission event. A WAIT does not. Waiting is possible only at nodes declared waitable and retains incoming context. Thus circling may be necessary when a destination opens later. The full-road smoke fixture declares no waits; this is a disclosed fixture choice and does not alter prior benchmark protocols.

## Geometry, time and numeric contract
Projected metre CRS and a complete regular raster grid are mandatory. Straight chord/raster intersections are reconstructed using exact rational arithmetic over represented input coordinates, including every interior crossing point's floor-selected cell and both positive-measure adjacent cells. Canonical floating segment encodings must exactly match the supplied coordinates/grid; gaps/overlaps/incorrect cells are rejected. No unmodeled spatial gap is tolerated. Raster half-open spatial cells select floor coordinates at a point; a corner can therefore select a third cell, which must also have support and pass constraints.

Integer and binary64 inputs have their exact represented values. Fraction arithmetic integrates and accumulates dose and compares budgets, so positive dose cannot disappear into large histories. Reports contain a rounded `dose` for display and `dose_exact` rational string as authoritative arithmetic evidence. This does not resolve measurement uncertainty or calibrate inputs. Road occupancy time endpoints are rational interpolations of exact represented leg start/end values.

Request departure, horizon, dwell and opening endpoints must **exactly** align with dt; tolerant near-lattice admission is rejected. The supported schedule envelope requires dt's rational numerator times the greatest absolute requested tick index to fit 53 bits. This makes all searched tick times exactly representable in binary64. Nonconforming grids return UNSUPPORTED_LATTICE; the solver does not coarsen time. Partial ceilings use rational arithmetic. A reversed fraction that cannot be serialized exactly is unsupported when reversal is permitted, rather than omitted from an optimum proof. ISO metadata must be timezone-aware; mission seconds share `time_origin`.

Hazards are right-continuous piecewise constant on breakpoint intervals. Flame, peak and known support are checked on closed occupied time spans and all breakpoints in them. At `valid_until`, the last interval's value is the explicit terminal convention. Points add no dose. Incident flux in kW/m² times seconds gives dose in kJ/m². Flux must be finite/nonnegative; flame/support must be actual Booleans; member IDs unique. An exact budget tie is allowed, a positive excess is rejected. No dose epsilon is used. Strict route continuity, travel durations and position fractions are independently checked without a permissive 1e-9 route gap.

Payload breakpoint endpoints are compared with validity metadata within 1e-9 seconds. This metadata tolerance does not extend hazard values: actual occupancy must lie inside the member's exact breakpoint extent, otherwise support is UNSUPPORTED. No tolerated temporal gap becomes zero flux or a checked route. Supply exactly matching endpoints in a mentor payload.

## Resource and destination constraints
Every member must meet flame, peak and cumulative dose constraints. Default `route_only` includes edges, waits and previously incurred dose but excludes destination dwell dose. Dwell still requires flame/peak/support and opening/horizon checks. Explicit `including_dwell` adds dwell dose. This scope is carried from the earlier benchmark; it is not a whole-life survival budget. Ember/secondary ignition channels are absent without eligible evidence.

Histories are indexed by scenario ID, not array index. Progress cannot decrease time or incurred dose, truncate/rewrite history, teleport, move faster than declared travel, or change incoming context without traversing a road. Changing scenario IDs requires explicit externally supplied conservative past-dose bounds for **every** new member, each at least the old maximum. This verifies the declared carry-forward assumption's shape/order; it cannot establish its physical validity. Without such a defensible external assumption, return UNSUPPORTED. No zero history is inferred.

## Exactness assumptions and limits
At equal node/incoming/time/admission, componentwise smaller dose dominates a label: both have identical future legal moves and additive costs. Different times, incoming edges or admission events cannot be merged. Scalar aggregate resource dominance is unsound; simultaneous binding member constraints are tested. The heap retains future arrivals even when current time layers are empty, repairing the known vector-search defect in the new implementation; an unchanged frozen repaired vector component is separately benchmarked on compatible cases.

Baseline uses full vector labels ordered by arrival time. Dijkstra has matched ordering/constraints; A* uses reverse directed static travel-time lower bounds ignoring hazards, turns, waiting and openings. These relaxations cannot overestimate feasible remaining travel. Complete exact search with full declared support yields conditional lattice optimality or complete modeled infeasibility. It establishes no continuous-time optimum. Missing support anywhere conservatively withholds global optimum/refusal certificates, even if a particular returned route can be checked. Turn-aware structural disconnection is distinct from thermal/resource refusal; at-issue violation is separately reported.

Activation theorem: if F is the full feasible set and F_A enforces only an active subset of exposure constraints while retaining all non-exposure constraints, F⊆F_A. An exact relaxed optimum passing all members is full-optimal; exact relaxed emptiness proves full emptiness. Adding a violated inactive member terminates after at most M additions only if every relaxation completes. The new generic adapter does not promote an activation implementation; `activation` returns UNSUPPORTED. The earlier verified eager/activation road planner remains the established road-scale recommendation.

One optional optimization removes an edge only when its directed turn-state has no legal suffix to any destination in a static relaxation. No timed/resource labels are merged. Any feasible route's edge states necessarily belong to this backward-reachable set; waits, hazards and openings cannot create a missing structural continuation. Context/occupied edges are retained for valid positioning, and witnesses are rechecked on the original graph. Assumptions fail if topology/turn rules or destination set changes without rebuilding, or if non-road moves are admitted. It is generic preprocessing, not a novelty claim; its time and extra check are charged. It remains off by default.

Wall, label, expansion, frontier and RSS caps are cooperative. Any truncation/cap gives TIMEOUT/unresolved, never an infeasibility proof. Preparation and mandatory checking are charged. A long individual validation/check step can overrun wall time before returning TIMEOUT; the official subprocess harness adds an external watchdog. RSS is measured process high-water memory, not allocation attribution. Independent exhaustive reference cap means UNRESOLVED; a checked witness does not independently certify a larger road optimum/refusal.

## Update and return behavior
Versions must increase; issue/availability times cannot regress. Time origin cannot change without reset. Each planning request/progress/update increments generation; older async results cannot commit over newer state. Caches are invocation-local, so hazard replacement cannot reuse prior exposure entries. Retained guidance must be independently rechecked at current position/time/exposure and current accepted hazard; older accepted versions are labelled explicitly after a rejected update.

This ordering guarantee assumes a serialized session owner for all mutations and completion callbacks. The object does not implement a thread synchronization primitive. It rejects delayed completions by version/generation/request equality under that execution policy, not arbitrary simultaneous unsynchronized thread access. Production asynchronous hosting must preserve this policy.

Return fallback traverses only the recorded original path in reverse. Every reverse direction, turn, current occupied fraction, actual return timing, support, incurred/return dose and required endpoint dwell/opening is checked. Missing reverse edges, forbidden reversal, current closure or absent support refuse this particular alternative. An undeclared zero-dwell return endpoint gets point thermal/support checks only; no verified shelter/opening requirement is invented. Positive dwell requires declared endpoint conditions, and cannot lower existing dwell. `plan_with_return` retains a primary TIMEOUT as unresolved while offering a separately budgeted checked return. It never concludes escape infeasibility from a timeout.
