# `outputs/dispatch/` — the three operational formats

Generated by `scripts/generate_dispatch_outputs.py` from the **committed**
`data/processed/rescue_routing.json`. Nothing is re-run and no number is
recomputed; this directory demonstrates the output FORMATS.

```
{timestamp}/
  MANIFEST.json                 clusters, checks, PDF results, what was sent (nothing)
  {NN}-{place-name}/
    dispatch_a4.html            A4 sheet for the 이장 — canonical
    dispatch_a4.pdf             same, via headless Chrome (see note below)
    broadcast_script.txt        마을방송 낭독 문구, <= 15 chars per line
    sms_drafts.txt / .json      family + welfare drafts, <= 90 chars — NEVER SENT
```

## ⚠ These "villages" are not 행정리

No authoritative administrative boundary data is available to this project, so
clusters are **DBSCAN spatial groupings of dispatch points, eps = 500 m**. A
cluster may span parts of two real villages or cover only part of one. Every
sheet states this in a bordered box; do not remove it.

## ⚠ Nothing here was transmitted

`sms.send()` is never called by the generator, requires an explicit
`approval_token`, and is additionally gated by `DEMO_MODE` (on by default).
`MANIFEST.json` records `nothing_was_sent: true`.

## What is committed

All HTML, text and JSON for every cluster (0.23 MB). Only the three largest
clusters' PDFs are committed — Chrome embeds a Korean font subset per file, so
33 PDFs come to 6.7 MB of regenerable output. Rebuild them all with:

```bash
python scripts/generate_dispatch_outputs.py
```

## Coverage

The committed source artifact carries all 24 unreachable points but only the top
20 of its 143 dispatch points, so these sheets cover 44 points. That is a
property of what Round 2 committed, not a sampling decision made here, and it is
printed on every sheet.
